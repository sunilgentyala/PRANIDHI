PRANIDHI

The Nudging Engine

Instead of an opaque "blocked," PRANIDHI offers up to three suggestions from four strategies, before enforcement.

1

Substitutive Reformulation

Replaces flagged fragments with typed placeholders so the user sees what a safe version looks like.

[REDACTED-PII] · [REDACTED-CREDENTIAL]
2

Decomposition

Splits a multi-entity prompt into independent sub-queries so no single interaction holds the whole risk.

names + revenue + strategy → three separate prompts
3

Abstraction Elevation

Lifts an instance-level question to a pattern-level one with no residual link to a real entity.

"Why did Acme Corp's Q3 revenue drop 14.7%?" → "What frameworks diagnose a single quarter's revenue contraction of this size?"
4

Tool Redirection

Routes the user to a safer path. Credentials never go to an external model.

"Use your organisation's secrets manager or internal vault."

Honest scope. In v0.2.0 these strategies are deterministic and template-based: no language model is called and confidence values are fixed design constants. A generative coaching model is on the roadmap and needs its own leakage safeguards.

Security posture

A guardrail is itself an attack surface. v0.2.0 models three trust boundaries and six threats to PRANIDHI itself, each with a regression test or a stated residual risk.

Trust boundaries (TB-1 untrusted input, TB-2 identity and policy attributes, TB-3 egress), per-layer controls, and the attack surface of the guardrail itself.

E1 Input obfuscationNFKC fold, strip format characters, decode percent, hex and Base64 as appended views, vendor credential patterns.Residual: reversal, ROT13, paraphrase.
E2 Policy tamperingDepartment thresholds clamped to the floor, policy cannot remove CREDENTIAL, fail-closed loading.Residual: protect the policy file at deployment.
E3 Identity spoofingRole and department are caller-supplied input.Residual: bind them to an authenticated identity provider.
E4 Feedback poisoningAdaptive thresholds are advisory and clamped to the enterprise floor.Residual: human review of proposals.
E5 Telemetry leakageHMAC-SHA256 user pseudonyms; no prompt text in records or the audit log.Residual: key management.
E6 Semantic evasionOut of scope for deterministic detection.Open: needs a semantic detector.

Quick start

Python 3.10 or newer. The output shown is real v0.2.0 output.

git clone https://github.com/sunilgentyala/PRANIDHI.git
cd PRANIDHI
pip install -e ".[dev]"
pytest tests/ -q        # 77 passed
Code
from pranidhi import PranidhiPipeline

pipeline = PranidhiPipeline(
    policy_path="policies/default.yaml")

r = pipeline.scan(
    "Analyse John Smith's account #4521-8876 "
    "for fraud patterns",
    {"role": "analyst", "department": "risk",
     "target_platform": "claude"})

print(r.disposition.value, round(r.risk_score, 3))
for s in r.suggestions:
    print(s.strategy.value, "|", s.confidence)
Output
AMBER 0.552
ABSTRACTION_ELEVATION | 0.7

# a prompt carrying a credential:
RED 0.723
TOOL_REDIRECTION | 0.95

The person's name is not detected: the pattern-based detectors cover credentials, account numbers, SSNs, emails, phone numbers, IPs and URLs, not names. This is a documented limitation.

It is not yet accepted or published. This repository is the reproducible source of truth for the framework's behaviour.
